# M09 Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tab "Rekomendasi" per proyek: kandidat + validasi + prioritas, perbandingan, kebijakan bobot, uji skenario aritmetika, draf usulan uji coba, semua dengan data tiruan.

**Architecture:** Logika murni tanpa React di `lib/mock/recommend.ts` dan `lib/mock/scenario.ts` (diuji unit). State tiruan bertambah lima koleksi dan satu reducer terpisah `rec-reducer.ts` yang dipanggil dari `reduce` (pola `rules-reducer`). Validasi dan peringkat **dihitung ulang saat render** dari state, tidak disimpan. Halaman memakai komponen Nora/Untitled UI yang ada.

**Tech Stack:** Next.js 16 App Router, React 19, Tailwind v4, Untitled UI (react-aria-components), Phosphor, Vitest. Tidak ada dependensi baru.

**Spec:** `docs/superpowers/specs/2026-10-18-m09-frontend-design.md`

Direktori kerja: worktree `nora-m09/apps/web`. Uji: `pnpm --filter web test`; build: `pnpm --filter web build`. Tidak ada `Co-Authored-By` Claude pada commit (aturan pengguna).

## Global Constraints

- Teks UI Bahasa Indonesia; ikon `@phosphor-icons/react`; kontrol 32px, judul 20px; pakai `Card`, `Pill`, `Banner`, `NoraModal`, `Table`, `Button` yang ada. Semua string data dirender sebagai teks.
- Bobot bawaan `{ relevance: .30, magnitude: .30, certainty: .15, effort: .15, risk: .10 }`; ambang kasus pendukung 30; sampel kecil bila `affected < 30`.
- `SCENARIO_DISCLAIMER = "Estimasi aritmetika pada kasus historis; mengabaikan efek kapasitas, antrean, dan perubahan perilaku."` tampil di setiap hasil skenario.
- Komponen usaha/risiko/Jev yang kosong **tidak pernah diisi nilai bawaan**.
- Aksi tulis: peran `analis` saja (`rec.edit`), proyek `aktif` saja (`acceptsData`); satu `AuditEvent` per sukses; reducer tidak melempar.
- Tanpa gulir horizontal di 1280px dan 1024px; status berikon + teks.
- Klarifikasi spec: `RecCandidate.ownerRole` bertipe `Role | null` (peran sistem proyek, ditampilkan lewat `ROLE_LABEL`), sebab anggota proyek hanya punya peran sistem. `ctx.memberRoles: Role[]` = peran anggota proyek.

## Review Focus

- Kandidat tanpa Jev (`belum_dinilai`) dan tanpa usaha/risiko: skor harus tetap terhitung dari komponen tersedia tanpa NaN; ditandai "n/5 komponen" (Task 1).
- Dua kandidat dengan skor identik: urutan stabil menurut id, apa pun urutan masukan (Task 1).
- Temuan tanpa kandidat tervalidasi: tabel peringkat menampilkan keadaan kosong, bukan tabel kosong (Task 4).
- Skenario dengan parameter di luar rentang (pct 0 atau 150, hari negatif, transisi tak dikenal): ditolak dengan galat, tidak membuat skenario (Task 3).
- `?ids=` pada perbandingan berisi satu id, lima id, id duplikat, atau id kandidat temuan lain: pesan dan tautan kembali, tidak crash (Task 5).
- Bobot kosong, negatif, atau > 1 pada editor kebijakan: tombol simpan nonaktif dengan pesan, tidak menyimpan NaN (Task 6).
- Proyek tidak `aktif` atau peran Pemilik proses/Administrator: tombol tulis hilang dengan penjelasan (Task 4, 6, 7, 8).
