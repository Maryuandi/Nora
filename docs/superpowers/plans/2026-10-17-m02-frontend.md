# M02 Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tambah layar Sumber data M02 (sumber, unggah, snapshot) dengan data tiruan di atas aplikasi M01 frontend.

**Architecture:** Perluas lapisan tiruan `apps/web/lib/mock/` (tipe, data awal, reducer murni, izin) lalu bangun lima layar di bawah `projects/[projectId]/` memakai `useProject()`, `useMock()`, komponen Untitled UI, dan gaya Nora yang ada. Hasil unggah ditentukan deterministik dari nama dan ukuran file.

**Tech Stack:** Next.js 16 App Router, TypeScript, Tailwind v4, Untitled UI (react-aria), Phosphor, Zod, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-17-m02-frontend-design.md`

## Global Constraints

- Semua teks UI Bahasa Indonesia. Ikon hanya `@phosphor-icons/react`. Judul halaman 20px, kontrol 32px (tombol `size="xs"`, input `size="sm"`).
- Reducer murni: tidak melempar galat; mengembalikan `{ state, error? }`. Tiap aksi sukses menambah **tepat satu** `AuditEvent`. Jam tetap `MOCK_TODAY`.
- Batas file 500 MB = `500 * 1024 * 1024` byte. Ambang usang 30 hari. Ambang perlu tinjauan > 5% baris ditolak.
- Format diterima: `.csv`, `.xes`, `.xes.gz`, `.zip` (ekstensi tidak peka huruf besar-kecil).
- Isi file tidak pernah dirender sebagai HTML; pratinjau memakai teks biasa.
- Tombol unggah, tambah sumber, konfirmasi, batal: hanya peran `administrator` atau `analis`, dan hanya saat proyek `aktif`.
- Jangan sentuh backend, `feat/m01a-foundation`, atau file di luar `apps/web` dan `docs/`.
- Commit tanpa baris Co-Authored-By Claude (preferensi pengguna).

## Review Focus

- Ekstensi huruf besar (`LOG.CSV`) dan nama tanpa ekstensi: yang pertama diterima, yang kedua galat "Format tidak didukung".
- File 0 byte dan tepat 500 MB: 0 byte galat "File kosong", tepat 500 MB diterima, 500 MB + 1 byte galat.
- Nama sama tetapi ukuran beda bukan duplikat; snapshot `dibatalkan` tidak dihitung sebagai duplikat.
- Nama sumber kosong/spasi saja dan nama kembar dalam satu proyek ditolak.
- Pemilik proses membuka URL snapshot langsung: boleh melihat, tidak ada tombol aksi. Bukan anggota: `NotFoundPanel`.
- Nama file sangat panjang terpotong dengan elipsis di tabel dan header, tidak merusak tata letak.

### Task 2: Aksi reducer sumber dan snapshot

**Files:**
- Modify: `apps/web/lib/mock/reducer.ts`
- Test: `apps/web/lib/mock/sources.test.ts` (baru)

**Interfaces:**
- Consumes: Task 1 (`Source`, `Snapshot`, `acceptsData`, `MockState`).
- Produces: `MockAction` bertambah
  `{ type: "createSource"; projectId: string; name: string }`,
  `{ type: "uploadSnapshot"; sourceId: string; fileName: string; sizeBytes: number }`,
  `{ type: "confirmSnapshot"; snapshotId: string }`,
  `{ type: "cancelSnapshot"; snapshotId: string }`.
  `reduce` mengembalikan untuk `uploadSnapshot` sukses `{ state, snapshotId: string }` dan untuk file kembar `{ state, duplicateOf: string }` (tanpa snapshot baru, tanpa audit); tipe hasil diperlebar menjadi `{ state: MockState; error?: string; snapshotId?: string; duplicateOf?: string }`. Ekspor `snapshotsForSource(s: MockState, sourceId: string): Snapshot[]` (terbaru dulu) dan `sourceFreshness(s: MockState, sourceId: string): { lastImportAt: string | null; latestEventAt: string | null; stale: boolean }`.

- [ ] **Step 1: Write failing tests** di `sources.test.ts`, satu `it` per baris (aturan nomor merujuk spec "Aturan reducer"):
  - `createSource`: sukses menambah sumber + 1 audit `sumber.tambah`; nama spasi saja → error, state sama; nama kembar (tak peka huruf) di proyek sama → error; proyek bukan `aktif` → error.
  - `uploadSnapshot`: `LOG.CSV` diterima; `data.txt` → "Format tidak didukung"; `a.csv` 0 byte → "File kosong"; 500 MB tepat diterima, 500 MB+1 → "Ukuran melebihi 500 MB"; `bagus.csv` 220000 byte → `siap_dipetakan` dengan `stats.rows === 1000` dan `rejected <= 10`; nama berisi `rusak` → `perlu_tinjauan` dengan `rejected / rows` ≈ 0,08; nama berisi `gagal` → `gagal` dengan `failureReason`; unggah file sama persis dua kali → kedua kali mengembalikan `duplicateOf` = id pertama, snapshot tidak bertambah, audit tidak bertambah; nama sama ukuran beda → bukan duplikat; snapshot `dibatalkan` dengan checksum sama tidak memicu duplikat; sumber yang sudah punya snapshot → `duplicateEvents ≈ 40%` rows dan `conflictEvents ≈ 0,2%`; sumber tanpa snapshot → `duplicateEvents === 0`; tiap unggah sukses menambah tepat 1 audit `snapshot.unggah`.
  - `confirmSnapshot`: `perlu_tinjauan` → `siap_dipetakan` + 1 audit `snapshot.konfirmasi`; dari `gagal` → error.
  - `cancelSnapshot`: dari `siap_dipetakan` → `dibatalkan` + 1 audit `snapshot.batal`, snapshot tetap ada; dari `dibatalkan` → error.
  - `sourceFreshness`: `stale` true saat `latestEventAt` 31 hari sebelum `MOCK_TODAY`, false pada 30 hari; snapshot `dibatalkan` tidak ikut menentukan `latestEventAt`.
  - Tidak ada aksi yang melempar pada id tak dikenal (error string).

- [ ] **Step 3: Implement** di `reducer.ts`. Checksum: hash 12 heks deterministik dari `fileName + ":" + sizeBytes` (fungsi kecil `fnv`, tanpa dependensi). `rows = Math.round(sizeBytes / 220)`.
