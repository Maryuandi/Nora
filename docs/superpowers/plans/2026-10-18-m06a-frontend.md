# M06a Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tab "Monitoring" › "Kepatuhan" per proyek: jalankan monitoring tiruan, lihat kepatuhan per aturan M04c, tren per bulan, kasus per status, dan panel asal-usul.

**Architecture:** `MonitoringRun` hanya menyimpan input beku (sumber, snapshot, pemetaan, periode, id versi aturan). Semua hasil dihitung oleh fungsi murni deterministik di `lib/mock/compliance.ts` saat halaman dibuka. Satu aksi reducer `runMonitoring`. UI mengikuti pola halaman M04c (`useProject`, `Card`, `Table`, `Pill`, `NoraModal`, `Banner`, Phosphor).

**Tech Stack:** Next.js 16 app router, React 19, Tailwind v4 + Untitled UI, Phosphor, vitest, `recharts@^3.10.1` (baru).

**Spec:** `docs/superpowers/specs/2026-10-18-m06a-frontend-design.md`. Semua path di bawah relatif ke `apps/web`. Branch `feat/m06a-frontend`.

## Global Constraints

- Frontend saja: tanpa backend, Temporal, Python, penyimpanan permanen.
- Aksi UI di-gate lewat `can()` di `lib/mock/permissions.ts`; `monitoring.run` hanya pada proyek `aktif` (`acceptsData`).
- Istilah: "Pelanggaran" hanya untuk versi aturan `disetujui`; selain itu "Tidak sesuai dengan acuan". Status kasus: `patuh`, `tidak_patuh`, `tidak_dapat_dievaluasi` (label UI "Patuh", "Tidak patuh"/istilah di atas, "Tidak dapat dievaluasi").
- Teks alasan persis: "Kolom sumber daya belum dipetakan (M03)", "Atribut {nama} belum dipetakan (M03)", "Kasus belum mencapai {aktivitas B}", "Tidak ada versi aturan yang berlaku pada awal kasus".
- Panel asal-usul memuat teks persis "Belum ada (M04f)" (paket konteks) dan "Kalender bawaan tiruan (M04a belum tersedia)". Tooltip kasus: "Penelusuran kasus (M05) belum tersedia".
- Teks UI Bahasa Indonesia; ikon Phosphor; kontrol 32px; judul 20px; semua string data dirender sebagai teks, nilai panjang terpotong dengan `title`.
- Determinisme: semua angka tiruan dari `hash` di `lib/mock/mapping.ts`; tidak ada `Math.random` atau `Date.now` di `compliance.ts`.
- Waktu tiruan tetap: `MOCK_TODAY` dan `now()` di reducer.
- Commit tanpa baris Co-Authored-By Claude / "Generated with Claude Code".
- Working tree awal berisi perubahan tak ter-commit milik pekerjaan lain (`permissions.ts`, `permissions.test.ts`, `format.ts`, `package.json`, `pnpm-lock.yaml`, plan M07). **Stage hanya berkas tugas ini per path; jangan `git add -A`.** Bila berkas yang harus diubah sudah kotor, berhenti dan tanya pengguna sebelum commit.
- Branch lain (M05a, M07, M08, M09) juga menambah ke `MockState`/`types.ts`/layout proyek; taruh tambahan M06a di baris terpisah agar konflik merge kecil.

- [ ] **Step 4: Implementasi `compliance.ts` dan ubah seed dua aturan di atas.** Aturan per fungsi, sesuai spec bagian "Aturan murni":
  - `mockCases`: irisan `[periodFrom, periodTo] ∩ [stats.timeFrom, stats.timeTo]`; kosong → `[]`. Jumlah = `round(round(stats.rows / 6) × hariIrisan / hariDataPenuh)`. Kasus ke-i: `start` = awal irisan + `hash(checksum + i) % hariIrisan` hari; diurutkan menurut `start` lalu id `CASE-0001…` diberikan setelah pengurutan; `end = null` bila `hash(checksum + i, 0x9e3779b1) % 10 === 0`, selain itu `start` + 1–30 hari.
  - `participatingVersions`: per `ruleKey` proyek, versi terbaru bila `disetujui`/`ditinjau`, ditambah versi lain yang `approvedAt` terisi.
  - `applicableVersion`: perbandingan string `YYYY-MM-DD`; beberapa cocok → `version` tertinggi.
  - `evaluateCase`: urutan pemeriksaan 1–4 di spec. Untuk langkah 3, "aktivitas B" = `to` (SLA) / `after` (urutan); kasus terbuka kena alasan bila `hash(version.id + c.id) % 2 === 0`. Langkah 4: proporsi tidak patuh `p = 3 + hash(version.id) % 43` persen; kasus tidak patuh bila `hash(version.id + c.id, 7) % 100 < p`. `ruleVersionId = version.id`.
  - `evaluateRun`: snapshot dan pemetaan dari `run.snapshotId`/`run.mappingId`; versi = `state.rules` yang id-nya di `run.ruleVersionIds` dan `ruleKey` cocok; kasus tanpa versi berlaku → `{ status: "tidak_dapat_dievaluasi", reason: "Tidak ada versi aturan yang berlaku pada awal kasus", ruleVersionId: null }`. Snapshot/pemetaan hilang → `[]`.
  - `summarize`: `byMonth` kunci `YYYY-MM` dari `start`, terurut naik; `reasons` terurut jumlah menurun.
